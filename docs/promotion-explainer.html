Promotion mode: from PR into develop to version

Traced with real data from the relx-promotion-test repo. Time flows left → right. Dots are commits, arrows are branches and merges.

Reading the diagram

  • • The main branch is production code only. Tags land here.
  • • The develop branch is development code. Features merge here.
  • • feature branches are created from develop.
  • • hotfix branches are created from main.
  • • relx/promote branches are cut by release preview-pr from develop (or a hotfix). Each carries code plus the version bump and changelog entry, and merges to main through one PR.
  • • release promote runs after the merge: it re-derives the version, refuses if the preview went stale, then creates the tag and GitHub Release.
  • • release forward-port opens a main → develop PR so hotfixes are not lost.

Where the version comes from

Commits between main and the promotion head decide the bump (fix: → patch, feat: → minor, breaking → major). The baseline is the newest tag matching tag_pattern at or above baseline_version. Baseline + bump = version: v0.6.0 + feat → v0.7.0, v0.7.0 + fix → v0.7.1.
